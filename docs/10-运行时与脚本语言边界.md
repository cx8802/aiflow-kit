# 运行时与脚本语言边界

`aiflow-kit` 不是只能用 Python。第一版 CLI 用 Python 做主控，但不同能力应该交给最适合的运行时，避免为了统一语言牺牲可靠性、性能或生态兼容性。

## 总原则

```text
Python 做编排和报告
BAT 做 Windows 会话环境
ripgrep 做文件扫描
Node 做前端生态
Go 做高性能单文件工具
Java/Maven 做 JVM 项目验证
```

所有工具都必须遵守项目级隔离：

- 不写用户全局配置。
- 不默认全局安装依赖。
- 缓存和下载目录优先落到 `.cache/`。
- 项目工具输出优先落到 `.tools/`。
- Windows 下不依赖 `.ps1`。

## Python 适合做什么

Python 是 `aiflow` CLI 主语言，适合：

- CLI 编排：`init`、`doctor`、`context`、`plan`、`review`、`verify`、`install-skills`。
- 读写 Markdown、TOML、JSON。
- 复制模板、复制 Skills、生成插件 manifest。
- 调用外部命令并记录退出码。
- 轻量项目扫描和 fallback。
- Git diff、风险规则、报告生成。

Python 不适合承担：

- 前端依赖安装和构建。
- Go/Java/Node 生态的包管理。
- 高频、大体量代码索引的核心实现。
- Windows 当前 shell 环境激活。

原因：Python 能做主控，但不应该替代每个生态自己的工具链。

## BAT 适合做什么

BAT 只负责 Windows 当前 `cmd` 会话环境：

- 设置 `GOCACHE`、`GOMODCACHE`、`GOBIN`。
- 设置 npm/pnpm/yarn/corepack cache。
- 设置 `MAVEN_USER_HOME`。
- 设置当前会话 `JAVA_HOME`。
- 可选设置 `HTTP_PROXY=http://127.0.0.1:10808`。
- 把 `.venv\Scripts`、`.tools\bin`、`.tools\npm-global\node_modules\.bin` 放到 PATH 前面。

BAT 不适合做：

- 大量文本解析。
- 复杂 JSON/TOML 读写。
- 跨平台业务逻辑。
- 复杂错误恢复。

BAT 的价值是：不被 PowerShell `.ps1` 执行策略拦截，并且能修改当前 `cmd` 会话环境。

## ripgrep 适合做什么

`ripgrep` 适合做只读文件扫描：

- `rg --files` 获取项目文件清单。
- 快速按关键词查找代码。
- 大仓库中替代 Python 递归遍历。

`aiflow context` 已经优先使用 `rg --files`，没有 `rg` 时回退到 Python。

`ripgrep` 不适合做：

- 结构化语言解析。
- 改写文件。
- 构建跨语言调用图。

## Node 适合做什么

Node 应用于前端和 JS/TS 生态：

- 运行 `npm.cmd install`、`npm.cmd run test`、`npm.cmd run build`。
- 调用前端工具：Vite、Next.js、ESLint、TypeScript、Playwright。
- 运行项目局部 JS/TS 脚本。
- 后续如需要，可以写 Node 小工具处理 `package.json`、workspace、前端 manifest。

Node 不适合做 `aiflow` 主控 CLI，除非项目后续明确转成 JS/TS 工具链。

约束：

- Windows 下用 `npm.cmd`，不要依赖 `npm.ps1`。
- npm cache/prefix 必须指向项目 `.cache/` 和 `.tools/`。

## Go 适合做什么

Go 适合后续做高性能、易分发的单文件工具：

- 大仓库扫描加速。
- 生成静态二进制辅助工具。
- 高并发文件处理。
- 可能的代码索引或 diff 预处理。

Go 不适合第一版主控：

- 当前项目核心是模板、Markdown、TOML、文件复制和 Git 调用，Python 足够。
- 过早引入 Go 会增加构建和发布复杂度。

约束：

- 不使用 `go env -w`。
- `GOBIN=.tools/bin`。
- `GOMODCACHE=.cache/go-mod`。
- `GOCACHE=.cache/go-build`。

## Java / Maven 适合做什么

Java/Maven 只用于 JVM 项目的验证和构建：

- `mvn test`
- `mvn package`
- `mvn verify`
- 后续检测 `pom.xml`、模块、插件配置。

Java 不适合做 `aiflow` 主控 CLI。Maven 也不应该被 Python 重新实现。

约束：

- 不修改系统 `JAVA_HOME`。
- 不修改用户 `%USERPROFILE%\.m2\settings.xml`。
- `MAVEN_USER_HOME=.cache/maven-user-home`。
- `maven.repo.local=.cache/maven/repository`。

## 能力分配表

| 能力 | 首选 | 备选 | 说明 |
| --- | --- | --- | --- |
| CLI 主控 | Python | Node | 第一版用 Python 标准库 |
| 模板复制 | Python | - | 稳定、简单 |
| TOML/JSON/Markdown 报告 | Python | Node | Python 3.11+ 有 `tomllib` |
| 当前 Windows 环境激活 | BAT | - | 不用 `.ps1` |
| 文件清单扫描 | ripgrep | Python | `rg` 快，Python fallback |
| Git diff 汇总 | Git + Python | - | Python 调用 Git |
| 前端构建/测试 | Node/npm.cmd | pnpm/yarn | 使用项目自己的脚本 |
| Go 项目验证 | Go | - | `go test ./...` |
| JVM 项目验证 | Maven/Java | Gradle | 不重写生态工具 |
| 高性能辅助工具 | Go | Rust | 第二阶段再考虑 |
| 浏览器截图验证 | Playwright/Node | Browser MCP | 第一版只记录命令和要求 |

## 实现建议

第一版只写 Python CLI 和 BAT 环境脚本。Go、Node、Java 先作为被调用工具，不作为主项目代码。

第二阶段如果遇到明确瓶颈，再拆：

- 文件扫描慢：优先加强 `ripgrep` 调用，不急着写 Go。
- 需要前端自动截图：增加 Node/Playwright helper。
- 需要单文件高性能工具：再写 Go helper，输出到 `.tools/bin`。
- 需要 Maven 深度分析：先读 `pom.xml`，必要时调用 Maven 命令。

## 不要做的事

- 不要为了“多语言”而每种语言都写一份主控逻辑。
- 不要用 Python 重写 npm、go、maven。
- 不要用 BAT 做复杂业务判断。
- 不要让 Node/Go/Java 工具默认写用户全局目录。
- 不要把临时代理、缓存、下载路径写入系统环境变量。
