# 记忆与上下文压缩

`aiflow-kit` 的记忆功能是文件型记忆，不是模型训练，也不依赖外部服务。

## 项目级记忆

默认写入当前项目：

```text
.aiflow/memory.md
```

适合保存：

- 项目架构结论。
- 常用命令。
- 业务约定。
- 已确认的实现边界。
- 数据库连接说明，但不保存密码、token、完整 DSN 等 secret。

命令：

```bat
aiflow memory add "后端入口在 src/server"
aiflow memory add "UI 改动必须跑 Playwright" --tag frontend
aiflow memory list
aiflow memory search "Playwright"
aiflow memory path
```

如果文本看起来包含敏感信息，默认会拒绝保存。数据库密码、token、密钥应该写入 `.aiflow/*.local.toml`，不要写入 memory。

## 全局记忆

只有显式 `--global` 才写入用户级：

```bat
aiflow memory add "Windows 上优先使用 BAT，不使用 ps1" --global
aiflow memory list --global
aiflow memory path --global
```

全局记忆只适合保存通用偏好：

- Windows 脚本偏好。
- 中国网站直连，海外资源使用 `http://127.0.0.1:10808`。
- 优先使用 `ripgrep`。
- 不污染全局 Go/Node/Java/Maven 环境。

不要把项目业务规则、数据库连接、内网地址或 secret 写到全局记忆。

## 上下文压缩

生成压缩上下文：

```bat
aiflow compact
```

同时刷新完整上下文并生成压缩文件：

```bat
aiflow context --compact
```

输出：

```text
.aiflow/context.compact.md
```

压缩内容来自：

```text
.aiflow/context.md
.aiflow/memory.md
.aiflow/plan.md
.aiflow/verify.md
.aiflow/review.md
.aiflow/agents/status.md
```

`context.compact.md` 是运行时摘要，默认加入 `.gitignore`，不提交远程。`memory.md` 可以作为项目知识沉淀提交，但提交前要确认不含敏感信息。

## Codex / Claude Code 读取顺序

项目模板已经更新为：

1. 优先读 `.aiflow/context.compact.md`。
2. 缺失时读 `.aiflow/context.md` 或运行 `aiflow context`。
3. 需要长期保存项目事实时运行 `aiflow memory add`。
4. 不把 secret 写入 memory。

## 配置

`.aiflow/config.toml`：

```toml
[memory]
enabled = true
project_file = ".aiflow/memory.md"
compact_file = ".aiflow/context.compact.md"
max_compact_entries = 30
```
