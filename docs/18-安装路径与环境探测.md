# 安装路径与环境探测

`aiflow-kit` 不应该假设源码一定在 `D:\code_work\aiflow-kit`。不同电脑、不同用户、不同磁盘上的路径都可能不同。

正确做法是：第一次安装时从当前打开的 `aiflow-kit` 项目自动探测真实路径，并写入本机 local 配置。

## 本机配置文件

运行：

```bat
aiflow env detect
```

会生成：

```text
.aiflow/env.local.toml
```

这个文件保存本机环境，方便查看和手工修改：

```toml
[paths]
project_root = "D:\\code_work\\aiflow-kit"
aiflow_kit_root = "D:\\code_work\\aiflow-kit"
scripts_dir = "D:\\code_work\\aiflow-kit\\scripts"
aiflow_dev_bat = "D:\\code_work\\aiflow-kit\\scripts\\aiflow-dev.bat"
aiflow_update_bat = "D:\\code_work\\aiflow-kit\\scripts\\aiflow-update.bat"
use_project_env_bat = "D:\\code_work\\aiflow-kit\\scripts\\use-project-env.bat"
```

`.aiflow/*.local.toml` 已被 gitignore，不提交到远程。

## 查看环境

```bat
aiflow env show
```

会显示：

- 当前项目路径
- aiflow-kit 源码路径
- scripts 目录
- Claude/Codex plugin 输出目录
- Python、Go、Node、npm、Java、Maven、ripgrep、git 的路径和版本
- 代理策略

## quick-install / update

快速安装脚本会先自动执行：

```bat
aiflow env detect
```

然后再安装全局 Codex / Claude Skills。

因此安装后的全局 Skills 中不会写死某个电脑上的旧路径，而是写入本机真实路径，例如：

```text
<actual-aiflow-kit-root>\scripts\aiflow-dev.bat
<actual-aiflow-kit-root>\scripts\aiflow-update.bat
```

## 当前项目与 aiflow-kit 源码路径

在其他项目中运行：

```bat
<aiflow-kit-root>\scripts\aiflow-dev.bat init
```

此时有两个路径：

- 当前工作目录：目标项目 root。
- `AIFLOW_KIT_ROOT`：aiflow-kit 源码 root。

`aiflow-kit` 会用脚本自身位置或 `AIFLOW_KIT_ROOT` 环境变量推导真实源码路径，不依赖硬编码。

## 可修改项

可以按需修改 `.aiflow/env.local.toml`：

- `paths.aiflow_kit_root`
- `paths.scripts_dir`
- `proxy.overseas_url`

修改后重新运行：

```bat
scripts\quick-install.bat
```

或：

```bat
scripts\aiflow-update.bat
```

就会把新的路径渲染到 Codex / Claude 全局 Skills。

## 不要做的事

- 不要把 `.aiflow/env.local.toml` 提交到远程。
- 不要在 Skill 源文件里写死某台电脑的绝对路径。
- 不要用 `setx` 写永久环境变量来解决当前项目路径问题。
- 不要把某个项目的数据库、token、内网地址写入全局 Skills。
