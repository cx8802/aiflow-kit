# 插件分发与安装流程

本项目把 Skills 作为源工作流，把插件作为分发单元。Claude Code 和 Codex 的插件清单不同，因此应生成两个目标包。

## 目标一：Claude Code 插件包

目录结构：

```text
aiflow-kit-claude/
├── .claude-plugin/
│   └── plugin.json
├── skills/
│   ├── project-analysis/SKILL.md
│   ├── implementation-plan/SKILL.md
│   ├── tdd-development/SKILL.md
│   ├── frontend-verify/SKILL.md
│   └── code-review-release/SKILL.md
└── README.md
```

最小 `plugin.json`：

```json
{
  "name": "aiflow-kit",
  "description": "AI coding workflow skills for analysis, planning, implementation, verification, review, and release.",
  "version": "0.1.0",
  "author": {
    "name": "aiflow-kit"
  }
}
```

本地测试：

```bat
claude --plugin-dir ./aiflow-kit-claude
```

安装验证：

```text
/help
/aiflow-kit:project-analysis
/reload-plugins
```

Claude Code 注意事项：

- `.claude-plugin/` 里只放 `plugin.json`。
- `skills/` 必须在插件根目录，不要放进 `.claude-plugin/`。
- 插件技能会带命名空间，例如 `/aiflow-kit:project-analysis`。
- 需要 marketplace 分发时，再补 `.claude-plugin/marketplace.json` 或独立 marketplace 仓库。

## 目标二：Codex 插件包

目录结构：

```text
aiflow-kit-codex/
├── .codex-plugin/
│   └── plugin.json
├── skills/
│   ├── project-analysis/SKILL.md
│   ├── implementation-plan/SKILL.md
│   ├── tdd-development/SKILL.md
│   ├── frontend-verify/SKILL.md
│   └── code-review-release/SKILL.md
└── assets/
```

最小 `plugin.json`：

```json
{
  "name": "aiflow-kit",
  "version": "0.1.0",
  "description": "Reusable AI coding workflow skills.",
  "skills": "./skills/"
}
```

可选增强：

```json
{
  "name": "aiflow-kit",
  "version": "0.1.0",
  "description": "Reusable AI coding workflow skills.",
  "skills": "./skills/",
  "interface": {
    "displayName": "AIFlow Kit",
    "shortDescription": "Analysis, plan, TDD, frontend verification, and release review workflows.",
    "category": "Engineering",
    "capabilities": ["Read", "Write"]
  }
}
```

## Codex repo 级本地安装

适合项目内试用：

```text
target-project/
└── .agents/
    └── skills/
        ├── project-analysis/SKILL.md
        ├── implementation-plan/SKILL.md
        ├── tdd-development/SKILL.md
        ├── frontend-verify/SKILL.md
        └── code-review-release/SKILL.md
```

Codex 会从当前工作目录向上扫描 `.agents/skills`。这适合把项目特定技能随仓库提交。

## Codex repo marketplace

适合把插件包放在同仓库中测试：

```text
target-project/
├── .agents/
│   └── plugins/
│       └── marketplace.json
└── plugins/
    └── aiflow-kit/
        ├── .codex-plugin/plugin.json
        └── skills/
```

`marketplace.json`：

```json
{
  "name": "local-aiflow",
  "interface": {
    "displayName": "Local AIFlow Plugins"
  },
  "plugins": [
    {
      "name": "aiflow-kit",
      "source": {
        "source": "local",
        "path": "./plugins/aiflow-kit"
      },
      "policy": {
        "installation": "AVAILABLE",
        "authentication": "ON_INSTALL"
      },
      "category": "Engineering"
    }
  ]
}
```

## 统一安装器行为

`aiflow install-skills` 应支持四类输出：

```bat
aiflow install-skills --target codex-repo
aiflow install-skills --target codex-user --confirm-global --allow-global
aiflow install-skills --target claude-user --confirm-global --allow-global
aiflow install-skills --target claude-plugin --output ./.aiflow/dist/aiflow-kit-claude
aiflow install-skills --target codex-plugin --output ./.aiflow/dist/aiflow-kit-codex
```

默认不做全局安装。无参数执行时只写当前项目：

```bat
aiflow install-skills
```

等价于：

```bat
aiflow install-skills --target codex-repo
```

用户级安装必须显式确认：

```bat
aiflow install-skills --target codex-user --confirm-global --allow-global
aiflow install-skills --target claude-user --confirm-global --allow-global
```

全局插件包只能包含通用流程 Skills，不能包含当前项目的命令、路径、业务规则或生成报告。项目定制内容应安装到 `.agents/skills/`、项目内插件包或 `.aiflow/`。

生成顺序：

1. 校验源 `skills/*/SKILL.md`。
2. 复制 Skills 到目标目录。
3. 为目标平台生成插件 manifest。
4. 输出安装报告。
5. 对 Codex repo marketplace，按需更新 `.agents/plugins/marketplace.json`。

## 版本策略

- `0.1.x`：Skills 和 CLI 命令仍可能变动。
- `0.2.x`：CLI 输出契约稳定。
- `1.0.0`：Skills 名称、标题、CLI 命令和配置键稳定。

破坏性变更必须写迁移说明：

- Skill 重命名。
- Markdown 输出标题变更。
- `.aiflow/config.toml` 键名变更。
- 插件 manifest 字段变更。

## 安全策略

- 第一版插件不内置 hooks。
- 第一版插件不内置 MCP server。
- 第一版插件不自动执行 shell 命令，命令执行由 agent 显式调用 `aiflow`。
- marketplace 分发前必须列出包含的 Skills 和潜在权限。
