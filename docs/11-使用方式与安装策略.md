# 使用方式与安装策略

`aiflow-kit` 有三种使用方式：

1. 不安装，直接用源码版。
2. 安装到当前 Python 环境，获得 `aiflow` 命令。
3. 把 Skills 和规则安装到某个目标项目。

推荐顺序是：先用源码版验证，再安装 CLI，最后按项目安装 Skills。

## 方式一：不安装，直接用源码版

适合当前开发阶段。

在任意目标项目中运行：

```bat
D:\code_work\aiflow-kit\scripts\aiflow-dev.bat --help
```

例如要在目标项目初始化：

```bat
cd /d D:\some-project
D:\code_work\aiflow-kit\scripts\aiflow-dev.bat init
D:\code_work\aiflow-kit\scripts\aiflow-dev.bat doctor
D:\code_work\aiflow-kit\scripts\aiflow-dev.bat install-skills
```

这个方式不安装包，不写全局环境变量，只是在当前命令里临时设置 `PYTHONPATH=D:\code_work\aiflow-kit\src`。

## 方式二：安装 CLI 到当前 Python 环境

适合你要频繁使用 `aiflow` 命令。

先进入 `aiflow-kit` 项目自己的隔离环境：

```bat
cd /d D:\code_work\aiflow-kit
scripts\use-project-env.bat
python -m pip install -e .
```

之后可以直接用：

```bat
aiflow --help
aiflow doctor
```

注意：这个安装写入当前 Python 环境。当前项目已经有 `.venv`，优先装到 `.venv`，不要用系统 Python 全局安装。

## 方式三：安装到具体项目中

目标项目需要的是规则、配置和 Skills，不一定需要把 CLI 也复制进去。

在目标项目中运行：

```bat
cd /d D:\some-project
aiflow init
aiflow doctor
aiflow install-skills
```

生成内容：

```text
AGENTS.md
CLAUDE.md
.aiflow/config.toml
.aiflow/context.md
.aiflow/context.compact.md
.agents/skills/
```

默认行为只写当前项目，不写用户全局目录。Playwright 运行时工具复用 `aiflow-kit/.tools/`。

## 是否需要配置环境变量

通常不需要手工配置永久环境变量。

如果使用源码版：

```bat
D:\code_work\aiflow-kit\scripts\aiflow-dev.bat
```

脚本会临时设置 `PYTHONPATH`。

如果想在当前 `cmd` 会话里直接输入 `aiflow`，可以临时把脚本目录放到 PATH：

```bat
set PATH=D:\code_work\aiflow-kit\scripts;%PATH%
aiflow --help
```

这里的 `aiflow` 实际调用的是：

```text
D:\code_work\aiflow-kit\scripts\aiflow.bat
```

这个方式只影响当前 `cmd` 窗口，关闭后失效。

如果使用已安装版：

```bat
aiflow
```

不需要 `PYTHONPATH`。

如果需要 Go、Node、Java、Maven、代理等项目级环境：

```bat
scripts\use-project-env.bat
```

需要代理：

```bat
scripts\use-project-env.bat proxy
```

不要使用 `setx` 写永久环境变量。

## 是否要全局安装

默认不建议全局安装。

| 内容 | 建议 |
| --- | --- |
| `aiflow` CLI | 开发期用源码版或安装到 `.venv` |
| 通用 Skills | 先安装到项目 `.agents/skills/` |
| 项目规则 | 必须项目级 |
| `.aiflow/config.toml` | 必须项目级 |
| 用户级 Codex Skills | 稳定后再考虑，必须 `--confirm-global` |
| Claude/Codex 插件包 | 可以生成到项目 `.aiflow/dist/` |

如果你确实想长期在任意目录输入 `aiflow`，有两个选择：

1. 把 `D:\code_work\aiflow-kit\scripts` 加到用户 PATH。
2. 把 CLI 安装到某个稳定的 Python 工具环境。

第一种最方便，但属于用户级 PATH 修改；第二种更像正式工具安装。项目未稳定前，推荐只用当前会话 PATH。

如果希望 Codex 或 Claude Code 在所有项目中都知道 `aiflow`，需要单独做全局接入。详见 [12-Codex与Claude全局接入.md](12-Codex与Claude全局接入.md)。

如果是在其他项目中让 Codex/Claude 直接安装 aiflow-kit，详见 [16-在其他项目中安装aiflow-kit.md](16-在其他项目中安装aiflow-kit.md)。

## 推荐日常流程

开发 `aiflow-kit` 本身：

```bat
cd /d D:\code_work\aiflow-kit
scripts\use-project-env.bat
python -m aiflow --help
```

在其他项目试用源码版：

```bat
cd /d D:\some-project
D:\code_work\aiflow-kit\scripts\aiflow-dev.bat init
D:\code_work\aiflow-kit\scripts\aiflow-dev.bat context
D:\code_work\aiflow-kit\scripts\aiflow-dev.bat install-skills
```

当前会话简化写法：

```bat
set PATH=D:\code_work\aiflow-kit\scripts;%PATH%
cd /d D:\some-project
aiflow init
aiflow context --compact
aiflow install-skills
```

把 CLI 安装到当前 `.venv` 后使用：

```bat
cd /d D:\code_work\aiflow-kit
scripts\use-project-env.bat
python -m pip install -e .
aiflow --help
```

## 一句话结论

- 不想安装：用 `scripts\aiflow-dev.bat`。
- 想当前窗口方便：临时 `set PATH=D:\code_work\aiflow-kit\scripts;%PATH%`。
- 想长期使用 CLI：安装到 `.venv`。
- 想让某个项目使用流程：在那个项目里运行 `aiflow init`、`aiflow install-skills` 和 `aiflow context --compact`。
- 不要默认写全局配置。
