# 浏览器伴随插件

`aiflow-kit` 的浏览器能力定位为 Chrome / Edge 可安装的 Extension Platform。插件只负责连接用户当前浏览器页面、采集用户显式确认的信息、执行受控 DOM 动作；自动化任务编排和结果落盘由当前项目的 `aiflow browser serve` 后台控制。

```text
Chrome / Edge extension
        |
        | localhost JSON + project token
        v
aiflow browser serve
        |
        v
.aiflow/browser/
```

## 能力边界

第一阶段支持：

- 连接本地 bridge：默认 `http://127.0.0.1:8765`。
- 鼠标选择页面元素：像开发者工具选元素一样高亮当前元素，单击后把元素摘要写入项目后台。
- 页面上下文采集：保存 URL、标题、选中文本和用户备注。
- 通用 adapter 动作：`extract`、`click`、`fill`、`wait`。
- 后台队列自动化：项目后台创建 pending job，插件在用户点击后读取并执行。

不支持也不应实现：

- 导出已登录网站的 auth token、session cookie 或其他 raw browser credential。
- 后台静默监控历史记录、全站内容或完整 DOM。
- 让浏览器插件直接改仓库代码、执行 shell、调用外部 API 或运行 agent。
- 默认把网页内容写入 `.aiflow/memory.md`。

登录态的正确用法是：插件在用户已登录的当前页面中执行受控页面操作，返回页面文本、元素选择器、动作结果等可审计数据，而不是把网站凭据取出来。

## 安装与打包

开发时查看扩展目录：

```bat
aiflow browser extension-dir
```

打包 Chrome / Edge 可安装产物：

```bat
aiflow browser pack --force
```

默认输出：

```text
.aiflow/dist/aiflow-browser-extension.zip
```

Chrome / Edge 开发者模式可以直接用 `Load unpacked` 加载 `extensions/browser/`。如果浏览器里已经安装过旧版本，修改源码后需要在扩展管理页点击重新加载。

## 连接流程

启动项目后台：

```bat
aiflow browser serve
```

后台会打印：

- bridge URL
- capture dir
- elements dir
- extension dir
- project token

插件侧栏只需要填：

- 桥接地址
- 项目令牌

点击 `连接` 后，插件调用 `GET /health`。连接成功后，主要操作就是 `选择页面元素`。

## 选择页面元素

用户点击侧栏的 `选择页面元素` 后：

1. 插件向当前 active tab 注入临时 picker。
2. 鼠标悬停的元素会被高亮。
3. 用户单击目标元素。
4. 插件读取元素摘要并调用 `POST /elements`。
5. bridge 写入 `.aiflow/browser/elements/<timestamp>-element.json`。

元素 JSON 包含：

- `url`
- `title`
- `selector`
- `tagName`
- `id`
- `className`
- `text`
- `href`
- `value`
- `attributes`
- `rect`

`password` 和 `hidden` 输入框的 `value` 不会被写回。插件不读取 cookie、localStorage、sessionStorage 或请求头。

## Bridge 协议

所有写入端点都需要：

```text
X-Aiflow-Token: <project token>
```

端点：

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/health` | 检查 bridge 和项目状态 |
| `POST` | `/captures` | 写入一次页面 capture |
| `POST` | `/elements` | 写入一次鼠标选中的页面元素 |
| `GET` | `/automation/next` | 读取下一条待执行自动化任务 |
| `POST` | `/automation/<id>/result` | 回写自动化任务结果 |

`POST /elements` 示例：

```json
{
  "url": "https://example.test/app",
  "title": "Demo App",
  "selector": "main > button:nth-of-type(1)",
  "tagName": "button",
  "id": "submit",
  "className": "primary",
  "text": "提交",
  "attributes": {
    "type": "button",
    "data-testid": "submit"
  },
  "rect": {
    "x": 10,
    "y": 20,
    "width": 100,
    "height": 30
  }
}
```

响应：

```json
{
  "element": ".aiflow/browser/elements/20260521-220501-element.json"
}
```

## 自动化队列

项目后台创建任务：

```bat
aiflow browser automate --step "fill;;#search;;aiflow" --step "click;;button[type=submit]" --step "wait;;;;1000" --step "extract;;main"
```

任务写入：

```text
.aiflow/browser/actions/pending/<job-id>.json
```

插件高级功能里可以手动执行下一条，也可以启动轮询执行器。执行完成后，bridge 把任务移到：

```text
.aiflow/browser/actions/completed/<job-id>.json
```

这条链路的控制权在项目后台，插件只是当前浏览器页面的执行端。

## 目录边界

扩展源码：

```text
extensions/browser/
```

项目本地输出：

```text
.aiflow/browser/
├── captures/
├── elements/
├── actions/
└── token
```

`.aiflow/browser/` 由 `.gitignore` 忽略。需要把某条网页结论提交到仓库时，应转写到文档、计划、测试或明确的项目 memory 中。

## 依赖策略

扩展运行时保持零 npm 依赖，直接使用 Manifest V3、静态 HTML/CSS/JS、Chrome extension API 和 adapter JSON。`extensions/browser/package.json` 只提供开发检查脚本。

后续如果需要 TypeScript、bundle、lint 或 Playwright 扩展 E2E，可以在 `extensions/browser/` 增加开发依赖，但不能让浏览器运行时依赖 Node。
