# 项目级多语言环境配置

本项目需要同时考虑 Python、Go、Node、Java、Maven 等工具。当前机器已经有全局 Go、Node、Java、Maven，Python 也已有 `.venv`。为了避免污染全局环境，本项目采用“全局只提供二进制，项目内保存缓存和依赖”的方式。

本项目不使用 `.ps1` 作为环境激活脚本，因为 Windows PowerShell 执行策略可能阻止脚本运行。项目级环境统一使用 `.bat`。

## 目标

- 不使用 PowerShell `.ps1` 激活脚本。
- 不使用 `go env -w`。
- 不使用 `npm install -g` 写入用户全局目录。
- 不使用 `npm config set -g`。
- 不使用 `setx` 修改永久环境变量。
- 不修改用户级 Maven `%USERPROFILE%\.m2\settings.xml` 或全局仓库。
- 不修改系统级 `JAVA_HOME`。

## 使用方式

推荐用 `cmd.exe` 进入项目并激活环境：

```bat
cd /d D:\code_work\aiflow-kit
scripts\use-project-env.bat
```

静默模式：

```bat
scripts\use-project-env.bat quiet
```

如果当前网络需要代理，可以启用本项目约定的本地代理 `127.0.0.1:10808`：

```bat
scripts\use-project-env.bat proxy
```

静默并启用代理：

```bat
scripts\use-project-env.bat quiet proxy
```

如果当前在 PowerShell 中，不要直接执行 `.bat` 后继续在 PowerShell 里跑命令，因为子进程设置的环境变量不会回到 PowerShell。应进入一个已激活的 `cmd` 会话：

```bat
cmd /k scripts\use-project-env.bat
```

如果从 PowerShell 进入带代理的 `cmd` 会话：

```bat
cmd /k scripts\use-project-env.bat proxy
```

关闭这个 `cmd` 窗口后，环境变量就消失，不会污染全局。

## 项目内目录

```text
aiflow-kit/
├── .venv/                  # Python 虚拟环境，已存在
├── .cache/
│   ├── go-build/           # Go build cache
│   ├── go-mod/             # Go module cache
│   ├── npm/                # npm cache
│   ├── pnpm-store/         # pnpm store
│   ├── yarn/               # yarn cache
│   ├── corepack/           # corepack cache
│   ├── maven-user-home/    # Maven 用户目录
│   └── maven/repository/   # Maven local repository
├── .tools/
│   ├── bin/                # go install 输出目录
│   ├── npm-global/         # npm -g 的项目级 prefix
│   └── pnpm/               # pnpm home
├── .mvn/
│   ├── maven.config
│   └── jvm.config
├── .npmrc
└── scripts/use-project-env.bat
```

`.cache/` 和 `.tools/` 已加入 `.gitignore`，不会提交。

## Python

已有 `.venv`，激活脚本会把 `.venv\Scripts` 放到当前 `cmd` 会话 PATH 前面。

推荐：

```bat
scripts\use-project-env.bat
python --version
pip --version
```

不要全局安装 Python 包。后续项目需要 Python 依赖时，写入 `pyproject.toml` 或 `requirements.txt`，安装到 `.venv`。

## Go

项目级设置：

```text
GOCACHE=.cache/go-build
GOMODCACHE=.cache/go-mod
GOBIN=.tools/bin
GOTOOLCHAIN=local
```

推荐命令：

```bat
scripts\use-project-env.bat
go version
go env GOCACHE GOMODCACHE GOBIN GOTOOLCHAIN
```

安装 Go 工具时：

```bat
go install example.com/tool@latest
```

二进制会进入 `.tools/bin`，不会进入用户全局 Go bin。

不要使用：

```bat
go env -w GOBIN=...
go env -w GOPATH=...
```

这些会写入用户级 Go 配置。

## Node / npm / pnpm / yarn

项目级设置：

```text
NPM_CONFIG_CACHE=.cache/npm
NPM_CONFIG_PREFIX=.tools/npm-global
PNPM_HOME=.tools/pnpm
PNPM_STORE_DIR=.cache/pnpm-store
COREPACK_HOME=.cache/corepack
YARN_CACHE_FOLDER=.cache/yarn
```

Windows 上 npm 会生成 `.ps1` 和 `.cmd` shim。为避免 PowerShell 执行策略问题，统一使用 `npm.cmd`：

```bat
scripts\use-project-env.bat
node --version
npm.cmd --version
```

安装项目依赖时，优先使用项目依赖：

```bat
npm.cmd install
npm.cmd run test
```

需要临时执行工具时：

```bat
npx.cmd --yes <tool>
```

如果必须全局安装 Node 工具，也只安装到项目级 prefix：

```bat
npm.cmd install -g <tool>
```

安装结果进入 `.tools\npm-global`，不是用户全局目录。

不要使用：

```bat
npm config set -g prefix ...
npm install -g <tool>
```

除非已经激活项目脚本并确认 `NPM_CONFIG_PREFIX` 指向 `.tools\npm-global`。

## Java

项目使用全局 JDK 二进制，但不修改系统 `JAVA_HOME`。激活脚本会在当前 `cmd` 会话中根据 `java.exe` 自动设置：

```text
JAVA_HOME=<detected-jdk>
```

只对当前 `cmd` 生效。

检查：

```bat
scripts\use-project-env.bat
java -version
echo %JAVA_HOME%
```

不要使用：

```bat
setx JAVA_HOME ...
```

## Maven

项目级设置：

```text
MAVEN_USER_HOME=.cache/maven-user-home
maven.repo.local=.cache/maven/repository
```

`.mvn/maven.config` 已设置：

```text
-Dmaven.repo.local=.cache/maven/repository
```

激活脚本还会设置：

```text
MAVEN_USER_HOME=.cache/maven-user-home
```

检查：

```bat
scripts\use-project-env.bat
mvn --version
echo %MAVEN_USER_HOME%
```

如果当前目录已经有 `pom.xml`，可以进一步检查 Maven 本地仓库是否指向项目目录：

```bat
mvn help:evaluate -Dexpression=settings.localRepository -q -DforceStdout
```

不要修改用户级：

```text
%USERPROFILE%\.m2\settings.xml
%USERPROFILE%\.m2\repository
```

## 网络代理

如果网络访问 GitHub、npm、Go module、Maven Central 等资源较慢或失败，可以使用本地代理端口 `10808`。代理只在当前 `cmd` 会话内生效：

```bat
scripts\use-project-env.bat proxy
```

脚本会设置：

```text
HTTP_PROXY=http://127.0.0.1:10808
HTTPS_PROXY=http://127.0.0.1:10808
ALL_PROXY=http://127.0.0.1:10808
NO_PROXY=localhost,127.0.0.1,::1
```

同时会给 Maven 当前会话追加：

```text
-Dhttp.proxyHost=127.0.0.1
-Dhttp.proxyPort=10808
-Dhttps.proxyHost=127.0.0.1
-Dhttps.proxyPort=10808
```

如果代理地址不同，可以在运行前覆盖：

```bat
set AIFLOW_PROXY_URL=http://127.0.0.1:10808
scripts\use-project-env.bat proxy
```

不要使用 `setx HTTP_PROXY ...` 或修改系统代理配置来解决当前项目的依赖下载问题。

## 污染风险检查

执行这些命令前要谨慎：

| 命令 | 风险 |
| --- | --- |
| `go env -w ...` | 写用户级 Go 配置 |
| `npm config set -g ...` | 写用户级 npm 配置 |
| `npm install -g ...` | 可能写用户级全局 prefix |
| `setx ...` | 写永久用户环境变量 |
| `setx HTTP_PROXY ...` | 把代理写成用户永久配置，影响所有项目 |
| 修改 `%USERPROFILE%\.m2\settings.xml` | 影响所有 Maven 项目 |
| 修改系统 `JAVA_HOME` | 影响所有 Java/Maven/Gradle 项目 |

本项目优先使用 `scripts\use-project-env.bat` 的当前 `cmd` 会话配置。

## ripgrep

系统已安装 `ripgrep` 时，`aiflow context` 会优先调用：

```bat
rg --files --hidden --glob !.git/**
```

这比 Python 递归遍历更快，适合大仓库。`ripgrep` 只作为扫描加速工具，不会写入全局配置；如果没有安装，CLI 会自动回退到 Python 遍历。
